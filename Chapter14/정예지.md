# Chapter 14: 가상 메모리

## 1. 연속 메모리 할당
프로세스에 연속적인 메모리 공간을 할당하는 방식

### 스와핑 
메모리에서 사용되지 않는 일부 프로세스를 보조 기억 장치의 스왑 영역으로 내보내고(**스왑 아웃**), 실행할 프로세스를 메모리로 들여보내는(**스왑 인**) 메모리 관리 기법

- 스왑 인 될 때는 스왑 아웃되기 전의 물리 주소와는 다른 주소에 적재될 수 있음  
- 프로세스들이 요구하는 메모리 주소 공간보다 더 작은 메모리로도 여러 프로세스의 동시 실행 가능

### 메모리 할당 방식
1. **최초 적합:** OS가 메모리 내의 빈 공간을 순서대로 검색하다가 적재할 수 있는 공간 발견 시 즉시 메모리 할당
2. **최적 적합:** OS가 메모리의 빈 공간을 모두 검색한 후 적재될 수 있는 공간 중 가장 작은 공간에 배치하는 방식
3. **최악 적합:** OS가 메모리의 빈 공간을 모두 검색한 후 적재될 수 있는 공간 중 가장 큰 공간에 배치하는 방식

### 외부 단편화 (연속 메모리 할당 방식의 단점)
프로세스를 할당하기 어려울 만큼 작은 메모리 공간들로 인해 메모리가 낭비되는 현상

- **해결 방안 1: 압축 (메모리 조각 모음)**
  - 여기저기 흩어져있는 빈 공간을 하나로 모으는 방식
  - 단점: 압축을 시행하기 위해서는 시스템이 하던 일을 중단해야 하며, 메모리를 옮기는 작업으로 인한 오버헤드 발생, 어떤 메모리를 어떻게 움직일지 결정해야 하는 문제 등
- **해결 방안 2: 가상 메모리 기법**
  - 페이징 기법

## 2. 페이징을 통한 가상 메모리 관리

- **가상 메모리:** 실행하고자 하는 프로그램을 일부만 메모리에 적재하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술
- **가상 메모리 기법:** 페이징, 세그멘테이션

### 페이징
프로세스의 논리 주소 공간은 **페이지(Page)** 단위로 자르고, 메모리 물리 주소 공간은 **프레임(Frame)** 단위로 자른다. 각 페이지(논리 공간)를 프레임(물리 공간)에 할당하는 기법

- **연속 메모리 할당 방식의 외부 단편화 원인 해결:** 각기 다른 크기의 프로세스가 메모리에 연속적으로 할당되는 문제 해결
- **스와핑:** 페이지 단위로 스왑 인/아웃 됨 (스왑 인을 **페이지 인**, 스왑 아웃을 **페이지 아웃**이라고 부르기도 함)
- **내부 단편화:** 페이지보다 작은 크기의 메모리가 할당된 경우 발생하는 낭비 공간

### 페이지 테이블
- **등장 배경:** 프로세스가 메모리에 불연속적으로 배치될 경우 CPU는 다음에 실행할 명령어를 찾기 어렵다.
- **페이징 시스템:** 프로세스가 물리 주소에 불연속적으로 배치되더라도, 논리 주소에는 연속적으로 배치되도록 페이지 테이블을 사용

### TLB (Translation Lookaside Buffer)
- **등장 배경:** 페이지 테이블은 메모리에 적재되어 있고, CPU 내의 페이지 테이블 베이스 레지스터가 그 주소를 가리키고 있다. (메모리 접근 시간이 2배 소요되는 문제)
- 일반적으로 MMU에 위치하며, 페이지 테이블의 **캐시 메모리** 역할
- 페이지 테이블의 일부 내용을 저장 (참조 지역성 - 최근 사용된 페이지 위주)
- **TLB 히트:** TLB 내에 논리 주소에 대한 페이지 번호가 있을 경우 (메모리에 접근할 필요가 없음)
- **TLB 미스:** TLB 내에 논리 주소에 대한 페이지 번호가 없을 경우 (메모리에 접근해야 함)

### 페이징에서의 주소 변환
- 하나의 페이지/프레임은 여러 주소를 포괄하고 있다.
- 특정 주소에 접근하기 위해 필요한 것:
  - **페이지 번호:** 어떤 페이지/프레임에 접근하고 싶은지
  - **변위:** 접근하려는 주소가 그 페이지/프레임으로부터 얼마나 떨어져 있는지
- 페이징 시스템에서는 모든 논리 주소가 기본적으로 `[페이지 번호, 변위]`로 이루어져 있다.

### 페이지 테이블 엔트리
페이지 테이블의 각각 행들을 말한다. 페이지 번호, 프레임 번호 외에 다음 정보들이 담긴다.

- **유효 비트:** 해당 페이지에 접근 가능 여부
  - 메모리에 페이지가 적재되어 있다면 유효 비트가 `1`, 아니라면 `0`
- **보호 비트:** 읽고 쓰기 각각의 가능 여부를 나타냄
  - 3개의 비트로 rwx(읽기/쓰기/실행) 각각의 접근 권한을 나타낼 수 있음
- **참조 비트:** CPU가 이 페이지에 접근한 적이 있는지 여부를 나타냄
  - 적재 이후 읽거나 쓴 페이지는 `1`, 단 한 번도 그러지 않았다면 `0`
- **수정 비트 (더티 비트):** 데이터를 쓴 적이 있는지 없는지
  - 변경된 적이 있다면 `1`, 변경/접근한 적이 없거나 읽기만 했다면 `0`
  - 페이지가 메모리에서 사라질 때 보조기억 장치에 쓰기 작업이 필요한지 판단을 위해 존재
  - `0`이라면: 스왑 아웃될 경우 추가 작업 없이 새로 적재된 페이지로 덮어쓰기만 하면 됨
  - `1`이라면: 메모리와 보조기억 장치가 서로 다른 값을 가짐 (스왑 아웃될 경우 변경된 값을 보조기억장치에 기록하는 작업이 추가되어야 함)

### 쓰기 시 복사 (Copy on Write)
프로세스를 fork하여 부모 프로세스와 동일한 복제본이 자식 프로세스로서 만들어질 때 사용되는 기법

- 자식 프로세스를 생성할 때 메모리 복제가 아니라 **페이지 테이블 복제**를 하면 메모리 복제 없이도 동일한 코드/데이터 영역 가리키기 가능
- 읽기 작업만 이어나간다면 이 상태 유지
- 쓰기 작업이 실행되면 그때 해당 페이지가 별도의 공간으로 복제되며, 해당 페이지가 할당된 프레임의 주소를 가리킴

## 3. 페이지 교체와 프레임 할당

### 요구 페이징 (Demand Paging)
처음부터 모든 페이지를 적재하는 것이 아닌, **필요한 페이지만 메모리에 적재**하는 기법

#### 동작 양상
1. CPU가 특정 페이지에 접근하는 명령어를 실행한다.
2. 해당 페이지가 현재 메모리에 있을 경우 (유효 비트가 `1`일 경우) CPU는 페이지가 적재된 프레임에 접근한다.
3. 해당 페이지가 현재 메모리에 없을 경우 **페이지 폴트(Page Fault)** 발생
4. 페이지 폴트 처리 루틴은 해당 페이지를 메모리에 적재하고 유효 비트를 `1`로 설정한다.
5. 다시 1번을 실행한다.

#### 순수 요구 페이징
아무런 페이지도 메모리에 적재하지 않은 채 무작정 실행하는 기법
- 첫 명령어를 실행하는 순간부터 페이지 폴트 발생
- 실행에 필요한 페이지가 어느 정도 적재된 이후로는 페이지 폴트 발생 빈도가 떨어짐

#### 요구 페이징이 안정적으로 작동하기 위한 조건
1. 페이지 교체 
2. 프레임 할당

### 페이지 교체 알고리즘
메모리에 페이지가 꽉 찼을 때 어떤 것을 내보낼지 결정하는 방법

- **페이지 참조열**에서 페이지 폴트 횟수를 통해 알고리즘을 수행할 수 있다.
  - *페이지 참조열:* CPU가 참조하는 페이지들 중 연속된 페이지를 생략한 페이지열

#### 종류
- **FIFO 페이지 교체 알고리즘:** 적재된 페이지 순서대로 교체하는 알고리즘
- **최적 페이지 교체 알고리즘:** 앞으로의 사용 빈도가 가장 낮은 페이지를 교체하는 알고리즘
- **LRU 페이지 교체 알고리즘:** 가장 오랫동안 사용되지 않은 페이지를 교체하는 알고리즘

> **Note:** 최적 페이지 교체 알고리즘은 미래를 예측해야 하므로 현실적으로 불가능하며, 다른 페이지 교체 알고리즘의 이론상 성능을 평가하는 목적으로 사용된다.

### 스래싱 (Thrashing)
지나치게 빈번한 페이지 교체로 인해 CPU 이용률이 낮아지는 문제 

- **발생 원인:** 각 프로세스가 필요로 하는 최소한의 프레임 수가 보장되지 않음
  - *예시:* 프레임이 부족하면 CPU 페이지 폴트는 자주 발생할 수밖에 없다 -> 반복된 페이지 교체 발생
- **해결 방안:** 운영체제는 스래싱이 발생하지 않게 하기 위해 각 프로세스들이 무리 없이 실행하기 위한 최소한의 프레임 수를 파악하고, 프로세스들에게 적절한 수만큼 프레임을 할당할 수 있어야 한다.

### 프레임 할당

#### 정적 할당 방식
프로세스 실행 과정 고려 없이 단순히 프로세스 크기, 물리 메모리의 크기만 고려한 방식
- **균등 할당:** 모든 프로세스에 동일한 프레임을 배분하는 방식
- **비례 할당:** 프로세스 크기에 따라 프레임을 배분하는 방식

#### 동적 할당 방식
프로세스의 실행을 보고 할당할 프레임 수를 결정한 방식
- **작업 집합 모델 기반 프레임 할당:** 작업 집합의 크기만큼만 프레임을 할당하는 방식
- **페이지 폴트율 기반 프레임 할당:** 페이지 폴트율에 상한선, 하한선을 정하고 그 내부 범위 안에서만 프레임을 할당하는 방식

> **작업 집합(Working Set):** 실행 중인 프로세스가 일정 시간 동안 참조한 페이지의 집합
