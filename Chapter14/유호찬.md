### 스와핑

메모리에서 사용되지 않는 프로세스를 스왑 영역으로 내보내고 그렇게 생긴 메모리상의 빈 공간에 다른 프로세스를 적재하여 실행하는 방식을 스와핑이라고 한다.

- 스왑 영역 : 프로세스들이 쫓겨나는 보조기억장치의 일부 영역
- 스왑 아웃 : 사용되지 않는 프로세스가 메모리 → 스왑영역으로 옮겨지는 것
- 스왑 인 : 스왑 영역에 있던 프로세스가 다시 메모리로 옮겨오는 것

스왑 아웃 되었던 프로세스가 다시 스왑 인될 때는 물리 주소가 달라질 수 있다.

스와핑 방식으로 프로세스들이 요구하는 메모리 주소 공간의 크기가 실제 메모리 크기보다 큰 경우에도 동시 실행이 가능해진다.

# 페이징을 통한 가상 메모리 관리

가상메모리는 실행하고자 하는 프로그램을 일부만 메모리에 적재하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술이다.

가상 메모리 관리 기법에는 크게 페이징과 세그멘테이션이 있지만 현재 대부분의 운영체제가 사용하는 기법은 페이징이다.

### 페이징이란

프로세스의 논리 주소 공간을 페이지라는 일정한 단위로 자르고, 메모리 물리 주소 공간을 프레임이라는 페이지와 동일한 크기의 일정한 단위로 자른 뒤 페이지를 프레임에 할당

<img width="607" height="397" alt="image" src="https://github.com/user-attachments/assets/b632dfd9-b166-49cf-8e15-d99abd5c04db" />

페이징에서의 스와핑은 프로세스 전체가 스왑 아웃/스왑 인되는 것이 아니라 페이지 단위로 동작한다.

스왑 아웃을 페이지 아웃, 스왑 인을 페이지 인이라고 부른다.

<img width="822" height="326" alt="image" src="https://github.com/user-attachments/assets/945251d6-2513-473c-aed1-d268e215845c" />

한 프로세스를 실행하기 위해 프로세스 전체가 메모리에 적재될 필요가 없고 실행에 필요한 일부 페이지만을 메모리에 적재하고 나머지를 보조기억장치에 남겨둘 수 있다. 이와 같은 방식으로 메모리보다 더 큰 프로세스를 실행할 수 있다.

### 페이지 테이블

프로세스가 메모리에 불연속적으로 배치되어 있다면 순차적으로 실행하기 어렵다. 

페이지 번호와 프레임 번호를 짝지어 주는 페이지 테이블을 통하여 페이지 번호만 보고 적재된 프레임을 찾을 수 있게 한다.

<img width="803" height="431" alt="image" src="https://github.com/user-attachments/assets/e07055c5-0aa7-450e-8ec7-9128a359d7ed" />

<img width="712" height="416" alt="image" src="https://github.com/user-attachments/assets/5703945b-1daf-4a06-8b7a-67d4aea00a35" />

CPU는 논리 주소를 순차적으로 실행하면 된다.

페이징은 외부 단편화 문제를 해결할 수 있지만 내부 단편화가 발생할 수 있다.

내부 단편화는 일정한 크기인 페이지로 자를 때 남는 메모리 낭비를 말한다.

페이지 크기를 줄이면 내부 단편화 크기가 작아지지만 페이지 테이블이 차지하는 공간이 낭비된다.

<img width="672" height="393" alt="image" src="https://github.com/user-attachments/assets/e38b8ad1-afd0-4f16-8f33-10ec6cc086a7" />

프로세스마다 각자의 프로세스 테이블을 가지고 있고 메모리에 적재되어 있다. 

CPU 내의 페이지 테이블 베이스 레지스터(PTBR)은 각 프로세스의 페이지 테이블이 적재된 주소를 가리키고 있다.

프로세스 A가 실행될 때 PTBR은 프로세스 A의 페이지 테이블을 가리키고, 프로세스 B가 실행될 때는 PTBR이 프고세스 B의 페이지 테이블을 가리킨다.

<img width="732" height="292" alt="image" src="https://github.com/user-attachments/assets/a31062b9-98fc-4ed1-af5a-205f06a529fe" />

이렇게 페이지 테이블을 메모리에 두면 메모리 접근 시간이 두 배로 늘어난다.

이 문제를 해결하기 위해 CPU 곁에 TLB라는 페이지 테이블의 캐시 메모리를 둔다.

TLB는 페이지 테이블의 캐시이기 때문에 페이지 테이블의 일부 내용을 저장한다.

CPU가 발생한 논리 주소에 대한 페이지 번호가 TLB에 있을 경우 TLB 히트, 없을 경우 TLB 미스라고 한다.

TLB히트는 메모리 접근을 1번, TLB 미스는 메모리 접근을 2번 해야한다.

<img width="847" height="327" alt="image" src="https://github.com/user-attachments/assets/c445f4e7-7885-42ff-b027-c23db8e51b09" />

### 페이징에서의 주소 변환

특정 주소에 접근하려면 두 가지 정보가 필요하다.

1. 어떤 페이지 혹은 프레임에 접근하고 싶은지
2. 접근하려는 주소가 그 페이지 혹은 프레임으로부터 얼마나 떨어져 있는지

그래서 모든 논리 주소가 페이지 번호(page number)와 변위(offset)으로 이루어려 있다.

페이지 테이블을 통해 논리 주소<페이지 번호, 변위>를 물리 주소<프레임 번호, 변위>로 변환한다.

<img width="872" height="437" alt="image" src="https://github.com/user-attachments/assets/d79ef408-70b9-485f-809d-e69a86b1fad6" />

위 사진에서 논리 주소<5,2>에 접근하려 한다고 가정해보자.

페이지 테이블을 통해 논리 주소<5,2>를 물리 주소<1,2>로 변환하고 1번 프레임은 8번지부터 시작하므로 8번지로부터 2 떨어져있는 10번지에 CPU가 접근하게 된다.

### 페이지 테이블 엔트리

페이지 테이블의 각각의 행들을 페이지 테이블 엔트리라고 한다.

페이지 테이블 엔트리에는 페이지 번호, 프레임 번호 뿐 아니라 유효 비트, 보호 비트, 참조 비트, 수정 비트 등 중요한 정보들이 있다.

1. 유효 비트
    
    현재 해당 페이지에 접근 가능한지 여부를 알려준다.
    
    유효 비트는 현재 페이지가메모리에 적재되어 있는지 아니면 보조기억장치에 있는지를 알려준다.
    
    페이지가 메모리에 적재되어 있다면 1, 메모리에 적재되어 있지 않다면 0이 된다.
    
    메모리에 적재되어 있지 않은 페이지로 접근하려고 하면 페이지 폴트(page fault)가 발생하여 다음과 같은 과정을 거친다.
    
    1. CPU는 기존의 작업 내역을 백업한다.
    2. 페이지 폴트 처리 루틴을 실행한다. 
    3. 페이지 처리 루틴은 원하는 페이지를 메모리로 가져온 뒤 유효 비트를 1로 변경해준다.
    4. 페이지 폴트를 처리했다면 CPU는 해당 페이지에 접근할 수 있게 된다. 
    
    <img width="632" height="360" alt="image" src="https://github.com/user-attachments/assets/f4c88a59-9fda-4988-aa29-19a3b01d3e7a" />

2. 보호 비트
    
    페이지 보호 기능을 위해 존재하는 비트
    
    보호비트를 통해 읽기 전용일 경우 0, 읽기/쓰기가 가능하다면 1로 나타낸다.
    
    읽기 r, 쓰기 w, 실행 x 세 개의 비트로 더 복잡하게 나타낼 수 있다.
    
    <img width="776" height="355" alt="image" src="https://github.com/user-attachments/assets/7df20a40-754c-4c92-a177-7074c5eb0a87" />

3. 참조 비트
    
    CPU가 이 페이지에 접근한 적이 있는지 여부를 나타낸다.
    
    적재 이후 CPU가 읽거나 쓴 페이지는 1, 없으면 0으로 표현한다.
    

<img width="752" height="384" alt="image" src="https://github.com/user-attachments/assets/1434105c-a7ea-41c8-9bf0-a6a533975689" />

1. 수정 비트
    
    해당 페이지에 데이터를 쓴 적이 있는지 없는지 수정 여부를 알려준다. 더티 비트라고도 한다.
    
    변경된 적이 있으면 1, 없으면 0으로 표현한다.
    
    <img width="842" height="353" alt="image" src="https://github.com/user-attachments/assets/96fe928a-39fd-4e71-97bf-abb26d85bdc6" />

    수정 비트는 페이지가 메모리에서 사라질 때 보조기억장치에 쓰기 작업을 해야 하는지 판단하기 위해 존재한다.
    
    CPU가 메모리에 값을 쓴다면 보조기억장치에 존재하는 페이지와 다르므로 보조기억장치에 기록하는 작업이 추가되어야한다.

# 페이지 교체와 프레임 할당

프로세스들이 한정된 메모리를 효율적으로 이용할 수 있도록 불필요한 페이지를 선별하여 보조기억장치로 내보내야 하고, 프로세스들에 적절한 수의 프레임을 할당하여 페이지를 할당할 수 있게 해야한다.

### 요구 페이징

프로세스를 메모리에 적재할 때 처음부터 모든 페이지를 적재하지 않고 필요한 페이지만을 메모리에 적재하는 기법

1. CPU가 특정 페이지에 접근하는 명령어를 실행한다.
2. 해당 페이지가 현재 메모리에 있을 경우(유효비트 1) CPU는 페이지가 적재된 프레임에 접근
3. 없을 경우 (유효비트 0) 페이지 폴트 발생
4. 페이지 폴트 처리 루틴으로 해당 페이지를 메모리에 적재하고 유효 비트를 1로 설정
5. 다시 1번 수행

요구 페이징 시스템이 안정적으로 작동하려면 페이지 교체와 프레임 할당이 잘 되어야 한다.

### 페이지 교체 알고리즘

기본적으로 페이지 폴트를 가장 적게 일으키는 알고리즘을 좋은 알고리즘으로 평가

1. FIFO 페이지 교체 알고리즘
    
    가장 먼저 올라온 페이지부터 내쫓는 방식
    
    <img width="810" height="351" alt="image" src="https://github.com/user-attachments/assets/48839cd5-5383-41ad-9c65-c52198e88e33" />

2. 2차 기회 페이지 교체 알고리즘
    
    FIFO 페이지 교체 알고리즘의 변형 버전으로 기회를 한번 더 주는 방식
    
    가장 오래 머물렀던 페이지를 대상으로 하지만 해당 페이지의 참조 비트가 1일 경우(접근한 적 있는 페이지) 참조 비트를 0으로 만든 뒤 현재 시간을 적재 시간으로 설정한다.
    
3. 최적 페이지 교체 알고리즘
    
    앞으로의 사용 빈도가 가장 낮은 페이지를 교체하는 알고리즘
    
    사실상 예측하는 실제 구현이 불가능에 가까우므로 다른 알고리즘의 성능 평가 용도이다.
    
4. LRU 페이지 교체 알고리즘

### 스레싱과 프레임 할당

기본적으로 메모리가 크다면 페이지 폴트가 적게 발생하고 메모리가 작다면 페이지 폴트가 자주 발생한다.

이처럼 프레임이 부족하면 CPU는 페이지 폴트가 자주 발생하게 된다.

1. 스레싱
    
    프로세스가 실제 실행되는 시간보다 페이징에 더 많은 시간을 소요하여 성능이 저해되는 문제
    
    동시에 실행되는 프로세스 수를 증가하면 CPU 이용률이 높아지지만 필요 이상으로 늘리면 스래싱이 발생한다.
    
    <img width="521" height="325" alt="image" src="https://github.com/user-attachments/assets/b884eeed-0a90-4704-bb55-010263a8efe3" />

2. 프레임 할당 방식
    
    스래싱이 발생하는 근본적인 원인은 각 프로세스가 필요로 하는 최소한의 프레임 수가 보장되지 않았기 때문이다.
    
    프레임 할당 방식에는 각 프로세스에 동일하게 프레임을 할당하는 균등 할당, 프로세스 크기에 따라 비례하게 할당하는 비례 할당이 있다. 이 두 방식은 실행과정을 고려하지 않는 정적 할당 방식이다.
    
    프로세스 실행을 보고 결정하는 동적 할당 방식에는 작업 집합 모델과 페이지 폴트 빈도가 있다.
    
    1. 작업 집합 모델
        
        특정 시간 동안 주로 참조한 페이지 개수만큼 프레임을 할당하는 방식이다.
        
        <img width="1021" height="274" alt="image" src="https://github.com/user-attachments/assets/bbd538c9-2dfc-4b2e-ae33-773412c7c200" />

    2. 페이지 폴트 빈도
        
        상한선과 하한선을 정해서 페이지 폴트율이 상한선보다 높아진다면 프레임을 더 할당하고 하한선보다 낮아진다면 프레임을 회수하는 방식이다.
