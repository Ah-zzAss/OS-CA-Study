## Chapter10: 프로세스와 스레드

### 1. 프로세스

- 사용자가 볼 수 **있는** 공간에서 실행되는 **포그라운드 프로세스**, 사용자가 볼 수 **없는** 공간에서 실행되는 **백그라운드 프로세스**  

### 2. 프로세스 제어 블록 (PCB, process control block)
프로세스와 관련된 정보를 저장하는 자료구조,  
해당 프로세스를 **식별**하기 위한 **정보**들이 저장된다.

- 커널 영역에 생성된다.
- 운영체제는 **PCB로 특정 프로세스를 식별**하고, 해당 프로세스를 처리하는데 필요한 정보를 판단한다.
- 프로세스 생성 시에 만들어지고, 실행이 끝나면 폐기된다.

#### PCB에 담기는 정보

- **프로세스 ID (PID)**
    - 특정 프로세스를 식별하기 위해 부여하는 고유번호
- **레지스터 값**
    - 해당 프로세스가 실행하며 사용했던 레지스터 값들을 저장
    - 이전까지 진행했던 작업을 복원하기 위해 프로세스는 자신이 실행 차례가 돌아오면 이전까지 사용했던 레지스터의 중간값을 모두 복원
- **프로세스 상태**
    - 입출력 장치 사용을 위해 대기중인지, CPU를 사용하기 위해 대기중인지, ... 등의 정보를 저장
- **CPU 스케줄링 정보**
    - 언제, 어떤 순서로 CPU를 할당 받을지
- **메모리 관련 정보**
    - 프로세스가 메모리의 어느 위치에 저장되었는지에 대한 정보
- **사용한 파일과 입출력장치 목록**
    - 프로세스가 실행 과정 중 사용한 특정 입출력 장치 / 파일
    - 어떤 입출력 장치가 이 프로세스에 할당되었는지, 어떤 파일을 열었는지에 대한 정보

### 3. 문맥 교환

기존 프로세스의 문맥을 PCB에 백업하고, 새로운 프로세스를 실행하기 위해 문맥을 PCB로부터 복구하여 새로운 프로세스를 실행하는 것

- 여러 프로세스가 끊임없이 빠르게 번갈아가며 실행되는 원리
- **문맥**:  하나의 프로세스 수행을 **재개**하기 위해 기억해야할 정보

### 4. 프로세스의 메모리 영역

- **커널 영역**: 프로세스가 생성되면 프로세스 식별 정보인 PCB가 생성된다.

- **사용자 영역**: 프로세스가 코드/데이터/힙/스택 영역으로 나뉘어 저장된다.
    - **정적 할당 영역**(크기가 고정): 코드 영역, 데이터 영역
    - **동적 할당 영역**(가변) : 힙 영역, 스택 영역

#### 정적 할당 영역

- 크기가 고정되어 있다.

1.  **코드 영역 (텍스트 영역)**: 실행할 수 있는 코드, 기계어로 이루어진 **명령어**가 저장된다.
    - 데이터가 저장되는 것이 아니다.
    - **CPU가 실행할 명령어**가 담겨있으므로 쓰기가 금지되어 있다.
    - 읽기 전용 공간이다.

2. **데이터 영역** : 프로그램이 실행되는 동안 유지할 데이터가 저장된다.
    - 대표 예시: 전역 변수 (프로그램 전체에서 접근 가능)

#### 동적 할당 영역

- 실시간으로 크기가 변할 수 있다.
- 힙영역은 낮은 주소에서 높은 주소로, 스택 영역은 높은 주소에서 낮은 주소로 할당된다 -> 겹칠 일이 없다

1. **힙 영역**: 프로그래머가 직접 할당할 수 있는 저장공간
    - 힙 영역에 메모리 공간을 할당 했다면 언젠가는 해당 공간을 반환해야한다.
    - **메모리 누수**: 메모리 공간을 반환하지 않아 메모리 낭비

2. **스택 영역**: 데이터를 일시적으로 저장하는 공간
    - 대표 예시: 매개 변수, 지역 변수

### 5. 프로세스 상태

하나의 프로세스는 여러 상태를 거치며 실행된다.  
운영체제는 PCB를 통해 인식하고 관리한다.

#### 종류
- **생성 상태**: 프로세스를 생성 중인 상태, 이제 막 메모리에 PCB를 할당 받은 상태
- **준비 상태**: 당장이라도 CPU를 할당받아 실행할 수 있지만, 자신의 차례가 아니라 대기 중인 상태
- **실행 상태**: CPU를 할당 받아 실행 중인 상태
- **대기 상태**: 입출력 장치의 작업을 기다리는 상태, 입출력 작업은 CPU에 비해 느리다.
- **종료 상태**: 종료 상태, 운영 체제는 PCB와 프로세스가 사용한 메모리를 정리한다.

#### 프로세스 상태 다이어그램

(사진)

- 실행 상태의 프로세스는 할당된 일정 시간만 CPU 사용이 가능하다.
- **실행상태 -> 준비상태**: 프로세스가 할당된 시간을 모두 사용하여 타이머 인터럽트가 발생할 때
- **실행상태 -> 대기상태**: 실행도중 입출력 장치를 사용하여 해당 작업이 끝날때까지 기다려야할때

### 6. 프로세스 계층 구조

프로세스는 실행 도중 시스템 호출을 통해 다른 프로세스를 생성할 수 있다.

- **부모 프로세스**: 새 프로세스를 **생성한** 프로세스
- **자식 프로세스**: 부모 프로세스에 의해 **생성된** 프로세스

#### 자식 프로세스
- 부모 프로세스와 다른 프로세스이기 때문에 다른 PID를 가진다.
- 일부 OS에서는 자식 프로세스의 PCB에 부모 프로세스인 PID, PPID(Parent PID)가 기록되기도한다.
- 자식 프로세스도 다른 자식 프로세스를 생성할 수 있다.

#### 프로세스 계층 구조
자식 프로세스가 새로운 프로세스를 낳는 방식으로 여러 프로세스가 동시에 실행될 때, 트리 구조를 띈다.

(사진)

예를 들어,  
사용자가 다음의 과정을 거친다.

1. 사용자가 컴퓨터를 킨다
2. 로그인 창을 통해 로그인을 한다.
3. bash 셸을 킨다.
4. bash 셸에서 vim 프로그램을 실행한다,

그러면 프로세스 관점에서는 다음과 같이 실행된다.

1. 최초 프로세스가 생성된다
2. 로그인을 담당하는 자식 프로세스(A)가 생성된다.
3. A는 bash 셸 프로세스(B)를 자식 프로세스로 생성한다.
4. B는 vim 프로세스를 실행한다.

### 7. 프로세스 생성 기법

#### 시스템 호출

- `fork`: 자기 자신 프로세스의 복사본을 만드는 시스템 호출
- `exec`: 자신의 메모리 공간을 새로운 프로그램으로 덮어쓰는 시스템 호출

#### 자식 프로세스의 생성 방법

자식 프로세스들은 **복제와 옷 갈아입기**를 통해 실행된다.  
`fork`, `exec` 시스템 호출의 반복을 통해 이루어진다.

1. 부모 프로세스가 `fork`를 통해 자기 자신의 복사본인 자식 프로세스를 만든다.
2. 자식 프로세스는 부모 프로세스의 모든 자원들을 상속된다.  
    단, PID와 저장된 메모리 위치는 다르다.
3. 자식 프로세스는 `exec` 시스템 호출을 통해 새로운 프로그램으로 전환  
    (`exec`를 호출해서 코드 영역/데이터 영역의 내용이 실행할 프로그램 내용으로 바뀌고, 나머지 영역은 초기화된다.)

예를 들어,  
사용자가 bash shell에서 ls라는 명령어를 치는 상황  

1. shell 프로세스는 fork를 통해 자신과 동일한 프로세스(자식 프로세스)를 생성
2. 자식 프로세스는 ls 명령어를 실행하기 위한 프로세스로 바뀐다.
3. 메모리 공간은 ls 명령어를 실행하기 위한 내용이 채워진다.

> 부모 프로세스가 자식 프로세스를 fork한 뒤,  
부모/자식 프로세스 누구도 exec를 실행하지 않는 경우  
 -> 부모/자식 프로세스는 같은 코드를 병행하여 실행하는 프로세스가 된다.

### 8. 스레드

프로세스를 구성하는 실행 흐름 단위

- 하나의 프로세스는 여러 개의 스레드를 가질 수 있다.
- 하나의 프로세스에서 여러 개의 스레드를 동시에 실행할 수 있다.

- 최근 많은 운영체제는 CPU에 처리할 작업을 '프로세스'가 아닌 '스레드'단위로 전달한다.

#### 프로세스 내  스레드

- 스레드는 **프로세스 자원을 공유**한 채 **실행에 필요한 최소한의 정보만으로 실행**된다.
- 프로세스 내 스레드의 구성: **각기 다른** 스레드 ID, 프로그램 카운터를 비롯한 레지스터 값, 스택 => 스레드 마다 각기 다른 코드 실행 가능

(사진)

#### 멀티 프로세스와 멀티 스레드

멀티 스레드는 멀티 프로세스보다 메모리를 더 효율적으로 사용 가능하다.  

- **멀티 프로세스**: 여러 프로세스를 동시에 실행  
    - PID, 저장된 메모리 주소를 제외한 모든 자원이 복제되어 메모리에 적재된다.

- **멀티 스레드**: 여러 스레드로 프로세스를 동시에 실행  
    - 스레드는 같은 프로세스 내의 자원을 공유한다.  
    - 프로세스의 자원을 공유하면, 하나의 스레드에 문제가 생길 시 전체에 문제가 생길 수도 있다.

> 스레드 보다 더 까다로운 뿐, **프로세스들도 데이터 교환**이 불가능하지 않다.  
> - **프로세스 간 통신 (IPC)**: 같은 컴퓨터 내의 서로 다른 프로세스/스레드끼리 데이터를 주고 받는 것  
> - **공유 메모리(shared memory)**: 서로 공유하는 메모리 영역
