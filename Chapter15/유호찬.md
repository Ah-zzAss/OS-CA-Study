# 파일과 디렉터리

### 파일

파일은 보조기억장치에 저장된 관련 정보의 집합을 의미한다.

파일의 부가정보를 속성 또는 메타데이터라고 부른다.

1. 파일 속성과 유형
    
    파일 속성의 종류는 유형, 크기, 생성날짜, 마지막 접근 날짜, 마지막 수정 날짜 등등이 있다.
    
    파일 이름 뒤에 붙는 확장자를 통해 파일의 유형을 알린다. EX) .exe, .mp3, .cpp 등등
    
2. 파일 연산을 위한 시스템 호출
    
    파일을 다루는 작업은 운영체제에 의해 이뤄지며 생성, 삭제, 열기, 닫기 등 여러 시스템 호출을 제공한다.
    

### 디렉터리

파일들을 분류하고 관리하는 공간을 디렉터리라 하며 폴더라고도 부른다.

옛날 운영체제는 하나의 디렉터리만 존재하는 1단계 디렉터리만 존재했다.

현재는 트리 구조 디렉터리를 사용하며 최상위 디렉터리를 루트 디렉터리라고 부른다.

1. 절대 경로와 상대 경로
    
    그에 따라 파일 위치 및 이름을 특정 짓는 경로라는 개념이 생겼다.
    
    - 절대 경로
        
        루트 디렉터리에서 자기 자신까지 이르는 고유한 경로
        
    - 상대 경로
        
        현재 디렉터리부터 시작하는 경로
        
2. 디렉터리 연산을 위한 시스템 호출
    
    파일 연산처럼 디렉터리 연산을 위해 생성, 삭제, 열기, 닫기 등 여러 시스템 호출을 제공한다.
    
3. 디렉터리 엔트리
    
    디렉터리 또한 특별한 형태의 파일이다. 
    
    파일은 내부에 파일과 관련된 정보를 담고 있고, 디렉터리는 디렉터리에 담겨있는 대상과 관련된 정보를 담고 있다.
    
    디렉터리 테이블 형태로 파일 이름과 위치를 유추할 수 있는 정보가 각 엔트리(행)에 담겨있다.

# 파일 시스템

파일 시스템은 파일과 디렉터리를 보조기억장치에 저장하고 접근하게 할 수 있는 운영체제 내부 프로그램이다.

파일 시스템은 여러 종류가 있고 하나의 컴퓨터에서 여러 파일 시스템을 사용할 수 있다.

### 파티셔닝과 포매팅

1. 파티셔닝
    
    저장 장치의 논리적인 영역을 나누는 작업을 말한다.
    
    파티셔닝을 통해 나누어진 영역 하나하나를 파티션이라고 한다.
    
2. 포매팅
    
    파일 시스템을 설정하여 어떤 방식으로 파일을 저장하고 관리할 것인지 결정하고 새로운 데이터를 쓸 준비를 하는 작업
    
    포매팅할 때 파일 시스템이 결정된다.
    
    파티션마다 다른 파일 시스템을 설정할 수 있다.
    

### 파일 할당 방법

운영체제는 파일과 디렉터리를 블록 단위로 읽고 쓴다.

가장 작은 저장 단위는 섹터이지만 섹터는 개수가 너무 많고 작기 때문에 블록 단위로 관리한다.

<img width="406" height="353" alt="image" src="https://github.com/user-attachments/assets/7f064fa6-67bc-419d-b646-b2a3ea5a259f" />

블록에 파일을 저장할 때 크게 연속 할당과 불연속 할당이라는 두 가지 방법이 있다.

그리고 불연속 할당에는 연결 할당과 색인 할당이 있다.

<img width="811" height="329" alt="image" src="https://github.com/user-attachments/assets/a1122805-c060-4637-a044-9dceaf285ec5" />

1. 연속 할당
    
    단순하게 연속적인 블록에 파일을 할당하는 방식이다.
    
    디렉터리 엔트리에 첫 번째 블록 주소와 길이를 명시한다.
    
    <img width="602" height="288" alt="image" src="https://github.com/user-attachments/assets/fdac3abe-67f5-4582-bfa2-e8d06adcac54" />

    구현이 단순하지만 외부 단편화를 야기하는 문제가 있다.
    
    <img width="1169" height="270" alt="image" src="https://github.com/user-attachments/assets/0b0e4650-4944-4243-a344-971eee0a5290" />

2. 연결 할당
    
    불연속 할당의 일종으로 각 블록 일부에 다음 블록의 주소를 저장하여 가리키는 형태로 할당하는 방법
    
    디렉터리 엔트리에 첫 번째 블록 주소와 길이를 명시한다.
    
    <img width="639" height="309" alt="image" src="https://github.com/user-attachments/assets/4b8ade68-a8b9-4131-b827-b5820487a0ad" />

    외부 단편화 문제를 해결하지만 단점이 존재한다.
    
    1. 반드시 첫 번째 블록부터 하나씩 읽어야 해서 임의 접근 속도가 매우 느리다.
    2. 하드웨어 고장이나 오류 발생 시 해당 블록 이후 블록은 접근이 불가하다.
    
    따라서 오늘날에는 이를 조금 변형한 FAT 파일 시스템을 사용한다.
    
3. 색인 할당
    
    파일의 모든 블록 주소를 색인 블록이라는 하나의 블록에 모아 관리하는 방식
    
    색인 블록에 저장된 주소에 차례대로 접근하면 된다.
    
    디렉터리 엔트리에 파일 이름과 색인 블록 주소를 명시한다.
    
    <img width="617" height="348" alt="image" src="https://github.com/user-attachments/assets/b6cb2985-c92b-4a12-9bd0-c5425e28a864" />

    연결 할당과 달리 파일 내 임의의 위치에 접근하기 쉽다.

1. 유닉스 파일 시스템
    
    색인 할당 기반의 파일 시스템이다.
    
    유닉스 파일 시스템에서 색인 블록을 i-node라고 부른다.
    
    i-node에 파일 속성 정보와 15개의 블록 주소가 저장될 수 있다.

    i-node들은 파티션 내 특정 영역에 모여있다.
    
    <img width="644" height="116" alt="image" src="https://github.com/user-attachments/assets/8d881028-75ea-4999-8726-2de4bae47681" />

    부족하다면 13번째에는 단일 간접 블록 주소를 저장한다.
    
    단일 간접 블록이란 “파일 데이터를 저장한 블록 주소”가 저장된 블록을 의미한다.
    
    <img width="643" height="295" alt="image" src="https://github.com/user-attachments/assets/cf400397-35ec-4535-8d4b-3024cbcd7725" />

    <img width="556" height="377" alt="image" src="https://github.com/user-attachments/assets/15e45931-d208-4162-bee7-7150fb4e61de" />

    a.sh를 읽기 위해서 유닉스 파일 시스템은 루트 디렉터리의 i-node를 항상 기억하고 있다. 2번이라고 가정하고
    
    1. 루트 디렉터리에서 home파일의 i-node 번호를 통해 해당 i-node에서 home 디렉터리 위치를 파악한다.
    2. 같은 방식으로 최종적으로 a.sh의 i-node를 알아낸다.
    3. 해당 i-node에 저장된 주소를 하나씩 접근하여 a.sh를 읽는다.
