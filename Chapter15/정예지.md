# 파일 시스템

## 1. 파일과 디렉터리
운영체제는 파일과 디렉터리를 관리하기 위해 다양한 시스템 호출을 제공합니다.

### (1) 파일 (File)
- **정의**: 보조기억장치(SSD/하드 디스크)에 저장된 관련 정보의 집합이며, 의미 있고 관련 있는 정보를 모은 논리적 단위입니다.
- **구성 정보**:
    - **이름**: 파일을 식별하는 명칭
    - **실행 정보**: 파일을 실행하기 위한 데이터
    - **속성(메타데이터)**: 파일 관련 부가 정보
- **파일 속성 정보**:
    - **파일 유형**: 운영체제가 인식하는 파일 종류 (주로 확장자를 통해 구분)
    - **기타**: 크기, 보호 설정, 생성 날짜 등

### (2) 디렉터리 (Directory)
- **정의**: 파일을 관리하기 위해 사용되는 논리적 구조 (윈도우에서는 '폴더'라고 함)
- **구조**:
    - **1단계 디렉터리**: 초기 OS 구조로, 모든 파일이 하나의 디렉터리 아래에 존재
    - **트리 구조 디렉터리**: 최상위 루트 디렉터리(`/`)를 기점으로 계층적으로 구성
- **경로 (Path)**:
    - **절대 경로**: 루트 디렉터리부터 시작하는 경로
    - **상대 경로**: 현재 디렉터리부터 시작하는 경로
- **디렉터리 엔트리 (Directory Entry)**:
    - 디렉터리 내부에 담겨 있는 대상(파일/하위 디렉터리)과 관련된 정보를 담고 있습니다.
    - 보조기억장치에 **테이블 형태**의 정보로 저장됩니다.

---

## 2. 파일 시스템 개요
파일과 디렉터리를 저장하고 접근할 수 있게 하는 운영체제 내부 프로그램입니다. 대표적으로 FAT, 유닉스 파일 시스템 등이 있습니다.

### 보조기억장치 사용을 위한 준비 작업
1. **파티셔닝 (Partitioning)**: 저장 장치의 논리적인 영역을 구획하는 작업
    - 나누어진 각 영역을 **파티션**이라 하며, 파티션마다 다른 파일 시스템을 설정할 수 있습니다.
2. **포맷팅 (Formatting)**: 파일 시스템을 설정하여 저장/관리 방식을 결정하고 데이터를 쓸 준비를 하는 작업
    - **저수준 포맷팅**: 공장에서 수행되는 물리적 포맷팅
    - **논리적 포맷팅**: 파일 시스템을 생성하는 포맷팅 (이 과정에서 파일 시스템 종류가 결정됨)

## 3. 파일 할당 방법
운영체제는 파일과 디렉터리를 **블록(Block)** 단위로 읽고 씁니다. 하나의 파일은 하나 이상의 블록에 걸쳐 저장됩니다.

### (1) 연속 할당 (Contiguous Allocation)
- **방식**: 보조기억장치 내 연속적인 블록에 파일을 할당
- **디렉터리 엔트리**: 파일 이름, 첫 번째 블록 주소, 블록 길이를 명시
- **장점**: 구현이 단순함
- **단점**: **외부 단편화**를 야기함

### (2) 연결 할당 (Linked Allocation)
- **방식**: 각 블록의 일부에 다음 블록의 주소를 저장하여 연결 리스트 형태로 관리
- **장점**: 외부 단편화 문제 해결
- **단점**:
    1. **임의 접근 속도가 매우 느림** (반드시 첫 번째 블록부터 순차적으로 읽어야 함)
    2. **오류에 취약함** (하드웨어 고장 등으로 한 블록에 문제가 생기면 이후 블록 접근 불가)

### (3) 색인 할당 (Indexed Allocation)
- **방식**: 파일의 모든 블록 주소를 **색인 블록**이라는 하나의 블록에 모아 관리
- **디렉터리 엔트리**: 파일 이름과 색인 블록 주소를 명시
- **장점**: 파일 내 임의 위치에 접근하기 용이함

## 4. 파일 시스템의 종류

### (1) FAT 파일 시스템
- **특징**: 연결 할당의 단점을 보완한 방식
- **파일 할당 테이블(FAT)**: 각 블록에 포함된 다음 블록 주소들을 한데 모아 테이블 형태로 관리
- **동작**:
    - 파티션 앞부분의 FAT 영역에 다음 블록 정보가 있어 메모리에 캐시(Cache)하여 실행하면 접근 속도가 빨라짐
    - **경로 탐색 예시**: `/home/minchul/a.sh` 접근 시
        1. FAT 영역 확인
        2. 루트 디렉터리 영역 확인
        3. 데이터 영역의 `home` 디렉터리 확인
        4. `minchul` 디렉터리 확인 후 파일 접근

### (2) 유닉스 파일 시스템
- **특징**: 색인 할당 기반이며, 색인 블록을 **i-node (index-node)**라고 부름
- **i-node 구조**:
    - 파일 속성 정보와 **15개의 블록 주소**를 저장 가능
    - i-node마다 고유 번호가 부여되며 파티션 내 특정 영역에 모여 있음
- **데이터 블록 확장 방식**:
    - 데이터 저장 공간이 부족할수록 아래로 확장을 이어감
    1. **직접 블록 (1~12번째)**: 데이터 블록 주소를 직접 저장
    2. **단일 간접 블록 (13번째)**: 추가적인 데이터 블록 주소들을 저장하는 블록의 주소
    3. **이중 간접 블록 (14번째)**: 단일 간접 블록들의 주소를 저장하는 블록의 주소
    4. **삼중 간접 블록 (15번째)**: 이중 간접 블록들의 주소를 저장하는 블록의 주소
