# 교착 상태란

### 식사하는 철학자 문제

![image.png](attachment:2114fc35-87d2-4661-af9a-4fa14dc04f4b:image.png)

1. 계속 생각을 하다가 왼쪽 포크가 사용 가능하면 집어든다.
2. 계속 생각을 하다가 오른쪽 포크가 사용 가능하면 집어든다.
3. 왼쪽과 오른쪽 포크를 모두 집어들면 정해진 시간동안 식사를 한다. 
4. 식사 시간이 끝나면 오른쪽 포크를 내려놓는다.
5. 오른쪽 포크를 내려놓은 뒤 왼쪽 포크를 내려놓는다.
6. 다시 1번부터 반복한다.

모든 철학자가 동시에 포크는 집어들면 어떠한 철학자도 식사를 할 수 없는 상황이 발생한다.

모든 철학자는 다른 철학자가 포크를 내려놓을 때 까지 기다리게 되는 상황이 발생한다. 이러한 현상을 교착 상태라고 한다.

이 문제에서 철학자는 프로세스 혹은 스레드, 포크는 자원, 생각하는 행위는 자원을 기다리는 것에 빗대어 볼 수 있다.

![image.png](attachment:bcea058a-11e2-455b-9beb-fea550706bb5:image.png)

이러한 교착 상태를 해결하기 위해서는 교착 상태가 발생했을 때의 상황을 정확히 표현해 보고 근본적인 이유에 대해 알아야 한다.

### 자원 할당 그래프

자원 할당 그래프는 어떤 프로세스가 어떤 자원을 사용하고 있고, 어떤 프로세스가 어떤 자원을 기다리고 있는지 표현하는 간단한 그래프

![image.png](attachment:c4989f35-33d4-4332-a9c6-7189ef2db3b6:image.png)

1. 자원은 사각형, 프로세스는 원
2. 사용할 수 있는 자원의 개수는 점의 개수
3. 프로세스가 어떤 자원을 할당받았을 경우 자원 → 프로세스로 표시
4. 프로세스가 어떤 자원을 기다리고 있는 경우 프로세스 → 자원으로 표시

![image.png](attachment:f1bf79af-8b53-4ded-a6a7-95833d6bb54c:image.png)

교착상태가 발생한 상황은 자원 할당 그래프가 원의 형태를 나타내고 있다.

### 교착 상태 발생 조건

교착 상태가 발생할 조건에는 네 가지가 있다. 아래 조건 줄 하나라도 만족하지 않는다면 교착 상태가 발생하지 않지만, 모두 만족될 때 교착 상태가 발생할 가능성이 생긴다.

1. 상호 배제
    
    한 프로세스가 사용하는 자원을 다른 츠로세스가 사용할 수 없을 때
    
2. 점유와 대기
    
    자원을 할당받은 상태에서 다른 자원을 할당받기를 기다리는 상태
    
3. 비선점
    
    자원을 이용하는 프로세스의 작업이 끝나야만 비로소 이용할 수 있는 경우

# 교착 상태 해결 방법

### 교착 상태 예방

예방하는 방법은 교착 상태 발생 필요 조건 네 가지 중 하나를 충족하지 못하게 하는 방법과 같다.

1. 상호 배제
    
    모든 자원을 공유 가능하게 만든다는 말과 같다. 현실적으로는 어렵다.
    
2. 점유와 대기
    
    자원을 할당 받고 대기하지 못하게 하는 것이다. 자원을 모두 할당하거나 아예 할당하지 않는 방식
    
    자원이 필요해도 기다릴 수밖에 없는 프로세스와 사용되지 않으면서 오랫동안 할당되는 자원이 많아지기 때문에 자원의 활용률이 낮아진다.
    
    많은 자원을 사용하는 프로세스가 불리해진다. 많은 자원을 필요로 하는 프로세스는 기아 현상이 생긴다.
    
3. 비선점 
    
    비선점을 없애면 자원을 이용 중인 프로세스로부터 자원을 빼앗을 수 있다. 
    
    이 방식은 선점하여 사용할 수 있는 일부 자원에 대해서는 효과적이다.
    
    하지만 프린터 자원과 같은 경우는 다른 프로세스가 프린터 자원을 빼앗아 사용하기 어렵다.
    
    비선점 조건을 없애는건 다소 범용성이 떨어지는 방안이다.
    
4. 원형 대기
    
    모든 자원에 번호를 붙이고 오름차순으로 자원을 할당하면 원형 대기는 발생하지 않는다.
    
    나머지 방법에 비해 비교적 현실적이고 실용적인 방식이지만, 모든 자원에 번호는 붙이는 일은 간단한 작업이 아니고 어떤 번호를 붙이는지에 따라 자원 활용률이 떨어질 수 있다.
    
    ![image.png](attachment:bcb6691c-f0a7-435e-9c69-54360031322f:image.png)
    

교착 상태의 발생 조건을 원천적으로 제거하여 교착 상태를 사전에 방지하는 예방 방식은 교착 상태가 발생하지 않음을 보장할 수는 있지만 여러 부작용이 따른다.

### 교착 상태 회피

교착 상태 회피는 교착 상태가 발생하지 않을 정도로만 자원을 할당하는 방식.

교착 상태를 한정된 자원의 무분별한 할당으로 인해 발생하는 문제로 간주한다.

- 안전 상태 : 교착 상태가 발생하지 않고 모든 프로세스가 정상적으로 자원을 할당받고 종료될 수 있는 상태
- 불안전 상태 : 교착 상태가 발생할 수도 있는 상황
- 안전 순서열 : 교착 상태 이 안전하게 프로세스들에 자원을 할당할 수있는 순서

![image.png](attachment:d24c4016-6678-4954-843d-0145cfad3f29:image.png)

위와 같은 상황이라면 P2 - P1 - P3 순서로 남은 자원을 할당하면 안전하게 작업을 완료할 수 있으므로 안전 상태이고 안전 순서열은 P2 - P1 - P3라고 할 수 있다.

![image.png](attachment:065db714-6e56-483d-b9e6-fca85ed6f3f4:image.png)

P3에 먼저 자원을 하나 내주었을 경우 교착 상태가 발생할 위험이 있는 불안전 상태이다.

운영체제가 교착 상태를 회피하기 위해서는 시스템 상태가 안전 상태에서 안전 상태로 움직이는 경우에만 자원을 할당하면 된다.

### 교착 상태 검출 후 회복

교착 상태 검출 후 회복은 교착 상태 방생을 인정하고 사후에 조치하는 방식

프로세스들이 자원을 요구할 때마다 그때그때 모두 할당하며, 교착 상태 발생 여부를 주기적으로 검사한다. 그리고 교착 상태가 검출되면 그때 비로소 회복한다.

1. 선점을 통한 회복
    
    교착 상태가 해결될 때까지 한 프로세스씩 자원을 몰아주는 방식
    
    다른 프로세스로부터 자원을 강제로 빼앗고 한 프로세스에 할당하는 방식
    
2. 프로세스 강제 종료를 통한 회복
    
    가장 단순하면서 확실한 방식.
    
    교착 상태에 놓인 프로세스를 모두 강제 종료 하거나 교착 상태가 없어질 때까지 한 프로세스씩 강제 종료
    
    전자는 확실하지만 많은 프로세스들이 작업 내역을 일게 될 가능성
    후자는 작업 내역을 잃는 프로세스는 최대한 줄일 수 있지만 교착 상태가 없어졌는지 여부를 확인하는 과정에서 오버 헤드를 야기한다.
