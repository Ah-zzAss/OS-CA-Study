# 동기화란

### 동기화의 의미

협력적으로 실행되는 프로세스들은 동기화가 필수이다.

프로세스 동기화란 프로세스들 사이의 수행 시기를 맞추는 것

1. 실행 순서 제어 : 프로세스를 올바른 순서대로 실행하기
2. 상호 배제 : 동시에 접근해서는 안 되는 자원에 하나의 프로세스만 접근
    
    예를 들어 프로세스 A는 계좌에 2만원을 넣는 프로세스, 프로세스 B는 계좌에 5만원을 넣는 프로세스라 가정할 때 동기화가 이루어 지지 않는다면 프로세스 A가 이루어지는 도중에 잔액이 저장되지 않았는데 프로세스 B가 실행되어 엉뚱한 결과가 나올 수 있다.

### 생산자와 소비자 문제

생산자는 버퍼에 물건을 넣고 변수를 1 증가

소비자는 버퍼에 문건을 빼고 변수를 1 감소

둘다 10만번씩 실행한다면 변수가 그대로 유지되어야 하지만 동기화가 제대로 되지 않는다면 이상한 값이 남는다. 총합이라는 데이터를 동시에 사용하기 때문이다.

### 공유 자원과 임계 구역

위 문제에서 총합이라는 자원이 공유 자원이다. 공유 자원은 전역 변수, 파일, 입출력장치, 보조기억장치 등등이 될 수 있다.

동시에 실행하면 문제가 발생하는 공유 자원에 접근하는 코드 영역을 임계 구역이라고 한다.

두 개 이상의 프로세스가 임계 구역에 진입하고자 하면 둘 중 하나는 대기해야 한다.

<img width="873" height="336" alt="image" src="https://github.com/user-attachments/assets/bc5239d8-348d-465d-9ea9-c9ba816513d6" />

여러 프로세스가 동시 다발적으로 임계 구역의 코드를 실행하면 문제가 발생하는 것을 레이스 컨디션이라고 한다.

고급 언어를 저급 언어로 변환되어 실행되므로 여러 줄의 저급 언어가 실행되는 과정에서 문맥 교환이 일어나기 때문에 레이스 컨디션이 발생한다.

운영체제는 이러한 임계 구역 문제를 아래 세가지 원칙 하에 해결한다.

1. 상호 배게 : 한 프로세스가 임게 구역에 진입했다면 다른 프로세스는 임계 구역에 들어올 수 없다.
2. 진행 : 임게 구역에 어떤 프로세스도 진입하지 않았다면 임게 구역에 진입하고자 하는 프로세스는 들어갈 수 있어야 한다.
3. 유한 대기 : 한 프로세스가 임계 구역에 진입하고 싶다면 그 프로세스는 언젠가는 임게 구역에 들어올 수 있어야 한다. (무한정 대기 X)

# 동기화 기법

### 뮤텍스 락

동시에 접근해서는 안 되는 자원에 접근하지 않도록 만드는 도구를 뮤텍스 락이다. 일종의 자물쇠

뮤텍스 락은 하나의 전역 변수와 두 개의 함수로 구현할 수 있다.

- 자물쇠 역할 : 프로세스들이 공유하는 전역 변수 lock
- 임계 구역을 잠그는 역할 : acquire 함수
    
    프로세스가 임계 구역에 진입하기 전에 호출하는 함수
    
    만약 잠겨있다면 lock이 false가 될 때 까지 반복적으로 확인하고 열려있다면 true로 바꾸는 함수
    
    반복적으로 확인하는 것을 바쁜 대기(busy wait)이라고 한다.
    
- 임계 구역의 잠금을 해제하는 역할 : release 함수
    
    작업이 끝나고 잠긴 임계 구역의 lock을 false로 바꾸는 함수

# 세마포

뮤텍스 락은 하나의 공유 자원을 가정한 방식

세마포는 여러 개의 공유 자원을 가정한 방식

뮤텍스 락과 비슷하게 하나의 변수와 두 개의 함수로 구현

- 전역 변수 S : 임계 구역에 진입할 수 있는 프로세스의 개수
- wait 함수 : 임계 구역에 들어가도 좋은 지, 기다려야 할 지를 알려주는
- signal 함수 : 임계 구역 앞에서 기다리는 프로세스에 신호를 주는

<img width="916" height="234" alt="image" src="https://github.com/user-attachments/assets/55d0cb68-7902-4ce2-8f97-2388bf5eb1ce" />

<img width="934" height="164" alt="image" src="https://github.com/user-attachments/assets/8d7e95bc-6fda-4a03-9974-36935ffd7fd3" />

공유 자원이 없는 경우 프로세스는 무한정 S를 확인해야 한다.

이를 해결하기 위해 wait 함수에서 자원이 없을 경우 프로세스를 대기 상태로 만들고 대기 큐에 넣는다.

signal 함수에서 대기 중인 프로세스를 대기 큐에서 제거하고 준비 상태로 변경한 뒤 준비 큐로 옮긴다.

세마포를 이용하여 프로세스 질행 순서로 제어할 수 있다.

# 모니터

<img width="886" height="359" alt="image" src="https://github.com/user-attachments/assets/e3e64ead-170f-45e6-8e3d-e8b10f04265e" />

공유 자원과 공유 자원에 접근하기 위한 인터페이스를 묶어 관리한다.

프로세스는 반드시 인터페이스를 통해서만 공유 자원에 접근한다.

모니터에 진입하기 위한 큐를 만들고, 모니터 안에 항상 하나의 프로세스만 들어오도록 상호 배제를 위한 동기화를 제공한다.

<img width="728" height="410" alt="image" src="https://github.com/user-attachments/assets/69c67803-17a2-44cf-b4dc-9332c5bc4dbd" />

실행 순서 제어를 위해 조건 변수를 사용한다.

조건 변수로 wait과 signal 연산을 수행할 수 있다.

- wait : 호출한 프로세스를 대기 상태로 전환하고 조건 변수에 대한 큐에 삽입
- signal : signal은 wait를 호출하여 큐에 삽입된 프로세스의 실행을 재개하는 연산
